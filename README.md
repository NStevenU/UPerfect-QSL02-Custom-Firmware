## 공통 변경 사항

### Burn-in 기본값

Bank 2의 기본 Burn-in 플래그를 `0x022BD2: 0x01 -> 0x00`으로 변경했습니다. 이 변경은 펌웨어의 기본 공장 테스트 상태를 끄기 위한 것이며, NVRAM에 이미 저장된 상태까지 영구적으로 제거한다는 의미는 아닙니다.

### NVRAM 섹터 초기화

`0xFB000~0xFCFFF`를 초기화한 이미지에서는 공장모드 부팅, 설정 초기화, 부팅 지연이 재현되지 않았고 설정 저장도 확인했습니다. 이는 초기화된 NVRAM에서의 실기기 결과이며, 사용시간 기록(Item `0x0F`)이 장기간 다시 생성되지 않는다는 것까지 최종 입증한 것은 아닙니다.

### EDID 전면 교체 (패널 순정 데이터시트 특성 반영 및 VESA 표준 호환성 복원)

순정 펌웨어에는 제조사가 임의로 넣어둔 엉뚱한 EDID(16:9 규격 크기인 29×16cm, 이전 패널의 왜곡된 색도 좌표)가 남아있어, 운영체제 연결 시 해상도 비율 인식 왜곡이나 빗나간 컬러 프로파일이 생성되는 문제가 있었습니다.

이번 커스텀 펌웨어에서는 실제 장착된 **CSOT MNG007DA1-Q 패널의 공식 데이터시트 순정 광학 특성**을 추출하여 EDID를 처음부터 다시 구성했습니다:

- **색도 좌표 반영**: 데이터시트의 삼원색(Red: x=0.647 y=0.328, Green: x=0.301 y=0.603, Blue: x=0.142 y=0.054) 및 화이트포인트(x=0.313, y=0.329, D65) 좌표를 EDID에 반영했습니다. 이 변경은 운영체제가 패널 특성에 가까운 색 프로파일을 선택하는 데 도움을 줄 수 있지만, 측정기 없이 실제 색 정확도나 sRGB 커버리지를 보장하지는 않습니다.
- **물리 크기 정정**: 16인치 16:10 비율에 정확히 부합하는 `34cm × 22cm`로 수정 (기존의 16:9 29×16cm 왜곡 제거).
- **포트별 명칭 정리**: Type-C는 `UPERFECT USBC`, HDMI는 `UPERFECT HDMI`로 명확히 분리.
- **주사율 및 FreeSync 범위 정리**: Type-C는 60~144Hz, HDMI는 60~130Hz Range Limits 및 FreeSync 데이터 주입.
- **VESA 표준 기본 해상도(Established & Standard Timings) 복원**:
  - 데이터시트의 노트북 직결용 eDP 원본에는 누락되어 있던 VESA 기본 해상도들을 순정 롬 규격에 맞춰 재구성했습니다.
  - **Established Timings**: `640×480 @ 60Hz` (IBM VGA / 레거시 부팅), `800×600 @ 60Hz`, `1024×768 @ 60Hz` (표준 UEFI BIOS) 활성화.
  - **Standard Timings**: `1920×1080 @ 60Hz` (최신 메인보드 FHD UEFI GUI), `1920×1200 @ 60Hz` (16:10 WUXGA), `1680×1050 @ 60Hz`, `1280×720 @ 60Hz` (HD 720p) 등 표준 해상도 등록.
  - 이를 통해 PC 부팅 단계(POST) 및 메인보드 BIOS 설정 화면 진입 시 발생하던 신호 없음(No Signal) 문제를 해결하고 구형/콘솔 기기와의 호환성을 확보했습니다.

EDID에 가변 주사율 정보가 들어 있다고 해서 모든 GPU·모든 입력 경로에서 VRR이 활성화되는 것은 아닙니다. Type-C DP Alt Mode에서는 Windows와 macOS에서 VRR을 확인했지만, 이 HDMI 경로에서는 NVIDIA 환경에서 VRR/G-SYNC가 활성화되지 않았습니다.

HDMI EDID에는 약 129.997Hz의 고정 DTD도 포함되어 있어 Windows에서 130Hz로 표시될 수 있으며, FreeSync 상한 또한 130Hz로 설정되어 120Hz 및 130Hz 모드 모두에서 VRR 범위를 온전히 지원합니다.

## 0도와 180도 버전의 차이

두 파일은 서로 정확히 17바이트 다릅니다.

| 수정 오프셋 | Bank 및 주소 | 0도 값 | 180도 값 | 확인된 의미 |
| :--- | :--- | :---: | :---: | :--- |
| `0x022BC4` | Bank 02: `0x2BC4` | `0x0A` | `0x1A` | 사용자 설정 구조체의 회전 관련 값 변경 |
| `0x05FD5B~0x05FD6C` | Bank 05: `0xFD5B` | 원본 회전 처리 | 회전값 2(180도)를 반환하도록 수정 | 입력·부팅 시 180도 회전 경로 강제 |

180도 버전은 실제 장치에서 화면이 180도 회전하는 것을 확인했습니다. OSD는 회전시키지 않아 메뉴 아이콘과 UI가 정방향으로 표시됩니다. 이 결과는 해당 테스트 장치와 입력 조건에서 확인된 것이며, 모든 패널·모드 조합의 호환성을 보장하지 않습니다.

초기 분석에서 Page 20 레지스터의 Bit 7을 H-Flip으로 확인했지만, 해당 레지스터를 직접 조합하는 방식은 180도 패치의 구현으로 사용하지 않았습니다. `0x20FB` 직접 쓰기는 쓰기 거부(ErrorCode `0x207`)가 관찰되어 패치 대상으로 삼지 않았습니다.

## 확인된 동작

- NVRAM 초기화 후 하루 뒤 재부팅해도 설정 저장 및 정상 부팅
- 공장모드/Burn-in 자동 진입 미재현
- Type-C: Windows/macOS 연결 및 60~144Hz VRR 동작 확인
- HDMI: Windows/macOS 연결 및 색상 동작 확인
- HDMI: 60.01Hz, 120Hz, 약 130Hz 고정 모드 표시 확인
- HDMI: NVIDIA 환경에서 VRR 및 G-SYNC 미활성
- 180도 이미지: 화면 회전 확인, OSD 정방향 유지

## 아직 확정하지 않은 사항

- HDMI 2.0 경로에서 NVIDIA VRR/G-SYNC를 EDID 수정만으로 활성화할 수 있는지
- 사용시간 Item `0x0F`가 장기간 사용 후 다시 기록되는지
- 모든 GPU, 케이블, 절전 복귀, 입력 전환 조합에서의 호환성

따라서 이 이미지는 상용 제품용 공식 펌웨어가 아니라, 특정 장치에서 검증한 커스텀 펌웨어입니다. 원본 펌웨어를 보관하고, 플래시 실패 시 복구 가능한 장비와 절차를 준비한 뒤 사용하십시오.
